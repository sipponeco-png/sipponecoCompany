# browser-amazon-affiliate-operator

## 目的
ブラウザ版 Codex Cloud 上で、**APIキーなし**・**画像生成なし（またはプロンプト設計まで）**で、日本語Amazonアフィリエイト向けの記事本文を安定生成するためのワークフロー。

## 適用条件
- 依頼が「Amazonアフィリエイト記事」「商品比較記事」「生活課題→解決カテゴリ導線」のいずれかに該当する。
- 商品の真偽確認・価格確認を十分にできない場合は、具体商品名の推測をしない。

## 基本方針
1. **生活の違和感・悩み**から導入する（商品名から始めない）。
2. 読者の検索意図を分解し、悩み別に解決カテゴリを提示する。
3. 商品名・価格・型番は、Webで確認できない限り記載しない。
4. 記事構成は原則以下:
   - ストーリー起点
   - 検索意図の整理
   - カテゴリ比較
   - 選び方
   - 購入前の注意
   - まとめ
5. 品質チェックで以下を禁止:
   - 誇大表現（例: 絶対、完全、誰でも必ず）
   - 医療/安全の断定
   - 根拠薄い最上級表現（最強、No.1など）
   - Amazonロゴやブランドロゴ利用を前提にした指示

## 実行手順（Cloud向け）
1. テーマを受け取る。
2. `runs/<run-name>/departments/` に以下ログを作る。
   - `01-research.md`（読者課題、前提、未確認事項）
   - `02-structure.md`（見出し設計と導線）
   - `03-quality-check.md`（リスク表現確認）
3. 記事本文を `articles/<run-name>.md` に作成。
4. 画像生成可否を `runs/<run-name>/image-generation-feasibility.md` に記録。
5. 画像ファイル自体は生成しない。必要なら見出し別プロンプト案のみ記載する。

## 出力ルール
- 日本語Markdown。
- H2/H3を使う。
- 具体商品が未確認なら「カテゴリ別の選び方」に寄せる。
- 最後に「この記事で使う画像が欲しい見出し候補」を6個だけ列挙する。

## Cloudでの画像生成に関する扱い
- このスキルはデフォルトで**記事作成まで**。
- Cloud環境で標準画像生成ツール/APIなしの実行手段が確認できない場合、画像工程は「プロンプト案作成」までに限定する。


## 標準記事文字数ガイド
- 本番運用の標準記事は **20,000文字以上** を目標にする。
- 文字数を下げるのは、短文テストや構成確認など明示された検証タスク時のみ。
- 文字数を満たす際も、水増しではなく読者の購入判断に資する情報（生活シーン、判断軸、失敗回避、運用手順）を優先する。
